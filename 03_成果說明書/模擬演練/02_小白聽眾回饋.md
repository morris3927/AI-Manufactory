# 模擬演練 02｜小白聽眾回饋

> 角色：企管系大一學生（也可以想成來看展的家長）。沒進過工廠，不懂 AI 技術，用過 ChatGPT 寫報告。
> 情境：有人照著《成果說明書_初稿》跟我報告，我邊聽邊記下卡住的地方。
> 說明：以下引用的都是說明書原句；「建議改寫」只是小白希望聽到的講法，給團隊參考，說明書本身沒有改動。

---

## 先講整體感受

前面三分鐘我還跟得上：「工廠機器卡住了，系統很快找到人來修，還會提醒先把機器鎖起來」，這個畫面我聽得懂，也覺得有道理。

到了第三章，突然冒出 Jev、LLM、YOLO、L3.5、System 1、向量檢索、Box 題型……我就開始只看表格裡的粗體字，靠「好像很厲害」撐下去。到第五章測試，我已經放棄理解，只記得「61 項全部通過」。

最大的問題：**我一直不知道「沖床」「送料」「卡料」長什麼樣子**。整份報告都圍繞這件事，可是沒人告訴我那是一台什麼機器、料片卡在哪裡、為什麼伸手進去會受傷。

## 1. 逐章聽不懂的地方

| 「快思慢想」 | 聽過這本書名，但不知道跟工廠有什麼關係 | 這個比喻其實很好，建議在摘要就用一句話講清楚（見第 3 部分比喻） |

| 「Jev 不擅長算數」 | AI 不會算數？那怎麼相信它？ | 補一句「就像國文老師不一定擅長算數學，計算交給程式，判斷交給 AI」 |

| 「機率 > 0.7」「S2」 | 0.7 是 70%？S2 是什麼？要翻到附錄才知道 | 第一次出現 S1／S2／S3 時就用「綠燈／黃燈／紅燈」說明 |

| 「規則判定的嚴重度，Jev 只能升級、不能降級」 | 有點懂，但不知道為什麼重要 | 「AI 可以說『這比想像中嚴重』，但不能說『沒那麼嚴重，不用管』，寧可多叫人也不要漏掉」 |
| 「Jev 逾時或故障 → 系統退回『規則＋YOLO』照常派工」 | 懂 | 「就算 AI 當機，警報照樣會響」，很令人安心，可以講大聲一點 |

| 「由程式強制執行，不是靠提示詞」 | 提示詞是我在 ChatGPT 打的那些字嗎？ | 「不是跟 AI 說『請記得要安全喔』然後祈禱它聽話，而是系統直接鎖住，AI 想說也說不出來」——這點很重要，值得放大 |
| 「設施規則第 254 條」 | 又一個條號 | 小白版刪掉條號，只說「依法規定」 |

## 2. 整份聽完，我能不能用自己的話說出來？

### 我的複述

> 「這是一個給工廠用的 AI 系統。工廠裡有一種叫沖床的機器，鐵板常常會卡住。以前要等巡邏的人經過才發現，現在監視器加上機器的紀錄，AI 一秒就發現了，然後自動傳訊息給負責的師傅，還會告訴他『大概是哪個零件壞了』。師傅到現場後，手機上有一個像 ChatGPT 的小幫手，一開始一定會叫他先把機器關掉鎖起來，才會教他怎麼修，因為以前很多人直接伸手進去被夾傷。修好之後會把經驗存起來，下次新人也會修。
>
> 它用了好幾種 AI，有一個快的、一個會聊天的，簡單的事就不用 AI。而且很便宜，一個月才幾美元。這很重要，因為可以少停機、少受傷，而且老師傅退休或去國外開新廠時，經驗也能留下來。」

### 我的複述缺了或錯了什麼（＝報告沒傳達到的地方）

| 問題 | 說明 | 代表報告哪裡要加強 |
|---|---|---|
| **錯：「AI 一秒就發現」** | 我以為全部靠 AI，其實約 95% 是固定規則判斷，AI 只處理少數需要判斷的事。「快思慢想三層」我只記得「有快的有慢的」 | 三層分工的「為什麼」沒有被一個生活例子講透 |
| **缺：Jev 和 ChatGPT 到底差在哪** | 我只說「一個快的、一個會聊天的」，說不出「Jev 給的機率是可信的、不會亂答」這個核心賣點 | 「校準」是第二大改變，卻沒讓小白理解它的價值 |
| **缺：影像和數據互相確認** | 我沒提到「兩個來源都說有問題才派工，避免亂叫人」，也沒提到場景三（電腦說在跑、其實停了） | 「跨模態」這個詞擋住了理解，場景三的重要性沒講清楚 |
| **缺：AI 不能操作機器、最後由人決定** | 我記得「先上鎖」，但沒記住「AI 只看不碰、不能說可以開機」這條底線 | 這句「AI 是第二道眼睛」很好，但埋在 3.4 節的表格後面 |
| **缺：系統當機也不會漏警報** | 完全忘了 Jev 故障時會退回規則照常派工 | 可靠性的訊息藏在條列第四點，太低調 |
| **模糊：「派給負責的師傅」** | 我不知道它是看班表、看職位，還會在沒人接時自動往上找主管 | 「找對的人」的機制聽起來很普通，其實有巧思，需要舉例 |
| **模糊：效益數字** | 我只記得「很便宜」，不記得「每月多出 19 小時產能」「停機減少 45%」 | 效益缺少換算成錢或產量，企管背景聽眾抓不住 |
| **缺：目前還是模擬** | 我的複述聽起來像已經在工廠用了，其實全是模擬資料、部分實驗結果還在【待填】 | 誠實聲明只在開頭小字和第五、九章，口頭報告容易被略過 |
| **缺：隱私** | 我沒想到人臉會被模糊、不會用來打考績 | 家長／一般人最在意的點，報告沒有主動強調 |

**結論**：「做什麼」我大致說得出來（八成）；「為什麼重要」我只講得出「少受傷、經驗留下來」，而團隊最得意的兩個技術亮點（三層分工、校準機率）我幾乎沒聽懂。

## 4. 最印象深刻與最無聊的段落

### 最印象深刻

1. **4.1 的「可以直接伸手拿出卡住的料片嗎？」→ AI 回答「不行」**
   這是整份唯一讓我「看到畫面」又「有感覺」的地方。我能想像一個新人急著想把東西拿出來，AI 擋住他，救了他的手。建議這段當成整場報告的開場故事，而不是放在第四章中間。

2. **「AI 是第二道眼睛，不是第一道防線」**
   一句話就讓我放心：AI 不會亂搞，最後還是人做決定。這句話值得放在封面或摘要。

3. **「銲接本來就有火花，會一直誤報」**
   很好笑也很真實，讓我覺得團隊有在思考現場會發生什麼事，不是只在紙上設計。

4. **「一條產線一個月不到 US$5」**
   便宜到讓人懷疑，但很好記。換成台幣更有衝擊力。

5. **「卡料沒有公開的訓練資料，用這個方法不需要訓練就能判斷」**
   我原本差點錯過，回頭看覺得這是很聰明的解法，可惜被埋在技術條列裡。

### 最無聊（或最讓我放空）

1. **3.5 採用的 AI 工具與模型表**
   Ultralytics、OpenRouter、Ollama Cloud、Chroma、FastAPI、Next.js……對我來說就是一串看不懂的英文品牌名。評審可能需要，但口頭報告時唸出來，我會直接滑手機。

2. **3.2 架構圖 L0–L6＋L3.5**
   像在看大樓樓層指示牌，而且還有「3.5 樓」。沒有圖的情況下只有一堆縮寫，看不出流向。

3. **5.1 測試方法總覽（T0、E1–E7）**
   編號太多，而且結果還是【待填】，聽完等於什麼都沒得到。

4. **第八章 與初選構想的差異**
   我沒參加初選，這章對我是「你們內部的修改紀錄」。只有銲接火花那一列有趣。

5. **1 章摘要表裡的數量清單（13 個模組、40 份 SOP、96 段法規原文、61 項測試）**
   數字一多，反而一個都記不住。建議只留一個最有說服力的數字。
