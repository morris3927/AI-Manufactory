# 功能清單

> 版本：2026-10-20
> 彙整來源：`系統架構.md`、`01_初選問題處理.md`、`Jev整合規劃.md`、`04_Demo規劃.md`、`06_工廠規範調查.md`、`07_RAG知識庫資料.md`
> 這份是**開發的總表**：每個功能標清楚「要做到什麼程度、需要什麼資料、哪個時間點要完成」。

## 標籤說明

| 標籤 | 意思 |
|---|---|
| 🟢 現成 | 用現成套件或 API 就能做，主要是寫整合程式 |
| 🟡 需改 | 初選寫法要修改（理由見 `01_初選問題處理.md`） |
| 🏭 工廠化 | 要照真實工廠做法或法規設計（依據見 `06_工廠規範調查.md`） |
| 🎓 需訓練 | 需要訓練或微調模型 |
| 📦 需資料 | 需要找公開資料或自己產生資料 |
| 🧪 需驗證 | 做法可行性還要實測 |

**里程碑**
- **M1（10/30 成果說明書）**：最小閉環能跑，截圖和測試數據寫進說明書。
- **M2（11/15 決賽簡報）**：所有 Demo 場景完成，數據定稿。
- **M3（11 月 Demo Day）**：穩定度、備案、現場操作演練。

## 0. 技術選型（定案）

| 項目 | 選擇 | 理由 |
|---|---|---|
| 後端 | Python 3.13 ＋ FastAPI ＋ asyncio | 影像、AI 套件都在 Python；asyncio 方便同時跑多支攝影機 |
| 事件匯流 | 程式內的 asyncio 佇列，topic 名稱沿用 Kafka 設計（`vision.events`、`mes.logs`、`access.events`、`alerts`、`tasks`） | 初選已寫「原型用輕量佇列」；介面不變，正式導入可換 Kafka |
| 資料庫 | SQLite（SQLModel） | 單機 Demo 夠用，免架設 |
| 向量資料庫 | Chroma（本機） | 免架設、Python 直接用 |
| Embedding | `bge-m3`（多語、本機 CPU 可跑） | 中英文手冊混用 🧪 |
| 影像偵測 | Ultralytics YOLO（最新版） | 生態完整、訓練簡單 |
| 判斷模型 | Jev 1.14（OpenRouter Decisions API） | 見 `Jev整合規劃.md` |
| LLM | DeepSeek V4.1 Flash（Ollama Cloud） | 已實測，繁中回覆約 1.3 秒 |
| 前端 | Next.js ＋ WebSocket ＋ 圖表庫，深色戰情介面 | 初選 4.4 已寫 |
| 通知 | Discord（webhook 推播＋bot 按鈕接單） | 評審可以掃 QR code 加入頻道 |

## 12. M1（10/30）最小閉環範圍

**場景 2：沖床卡料**從頭到尾跑通：

```
攝影機模擬器播放卡料影片 ＋ Log 模擬器送料速率歸零
→ SE-4 Jev 看關鍵幀判定卡料 ＋ SE-5 Log 判定
→ RU-2④ 跨模態確認 → RU-1 S2 → RU-3 設備類 → RU-4 派給技術員
→ JV-1 根因前三名 → NT-1 Discord 推播 → LM-1 說明補發
→ AG-1/AG-2 Agent 先給 LOTO 清單，再引導排查
→ CL-1 Checklist → CL-3 寫回知識庫
→ UI-1/2/3 畫面全程同步；GV-2 每一步都有紀錄
```

再加上**場景 1：PPE 違規**（SE-1 → RU-1/3/4 → NT-1，不叫 LLM）。

M1 共需完成的 ID：IN-1/2/3/5、SE-1/2/4/5、RU-1/2/3/4/6、JV-1/2/3/4/5、KB-1/2、LM-1、AG-1/2/5/6、NT-1/3、WO-1、CL-1/3、GV-1/2/5、UI-1/2/3/4、EV-1/2/4/5。

## 13. 開工前要先解決的三件事

1. **影片素材**（IN-5）：卡料影片和 PPE 影片要去哪裡找、授權能不能用 → `03_資料集.md`
2. **Jev 看圖實測**（SE-4）：20 張正常與卡料圖片，看機率分不分得開、Box 準不準、延遲多少
3. **分工**：四位組員各自負責哪些模組 → `05_分工與時程.md`
