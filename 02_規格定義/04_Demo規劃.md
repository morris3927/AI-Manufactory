# Demo 規劃

> 定案日期：2026-10-20

## 0. 結論

**系統現場即時運作是主軸，預錄的整段操作影片只當備案。**

- **不使用實體攝影機（定案）**。改用「**攝影機模擬器**」：在控制台選一段影片指定給某一支「攝影機」，模擬器以真實速度（例如 15fps）逐幀送進系統，對系統來說就跟即時串流一樣。
- 影片送進去之後，YOLO 偵測、Jev 關鍵幀判斷、規則引擎、派工通知、維修 Agent **全部是現場即時運算**，評審可以隨時要求換一段影片或重來。
- Log 模擬器跟影片同步送出 MES Log（時間戳對齊）。
- 整段完整操作錄一份影片，網路或硬體出問題時才拿出來放。

**為什麼不能只放預錄影片**：簡章決賽規定「現場展示 AI 系統或原型之**實際運作方式**」，可行性（30%）以「功能驗證與實作成果」為主要依據。只放影片，評審無法互動，可行性分數會吃虧。

## 1. 現場配置

```
┌───────────── 攤位 ─────────────┐
│  [大螢幕 / 外接螢幕]            │  ← 戰情儀表板：4 格「攝影機畫面」＋ Kanban
│                                 │
│  [筆電] 控制台                  │  ← 組員操作：選影片 → 指定攝影機 → 開始播放
│                                 │
│  [手機 / 平板] 技術員視角        │  ← Discord 推播 ＋ 維修 Agent 對話
│  [評審自己的手機]               │  ← 掃 QR code 加入 Discord 頻道，親自收到派工通知
└─────────────────────────────────┘
```

### 1.1 攝影機模擬器

| 功能 | 說明 |
|---|---|
| 影片庫 | 每個場景準備 2–3 段影片（正常、異常、誤報情境），按產線分類 |
| 指定攝影機 | 把影片指派給「沖壓線 CAM-01」等虛擬攝影機，儀表板上就顯示成那支攝影機的即時畫面 |
| 即時播放 | 以真實時間逐幀送出（不是一次丟整段），系統只看得到「到目前為止」的畫面 |
| 循環播放 | 正常影片可以無限循環，當作背景；要觸發異常時切換成異常影片 |
| 同步 Log | 每段影片附一份 Log 腳本（例如第 12 秒送料速率開始下降），播放時同步送出 |

技術上：OpenCV 讀 mp4 → 依 fps sleep → 把幀放進與真實 RTSP 相同的介面。**正式導入時只要把影片來源換成 RTSP 網址**，後面的程式完全不用改。這點要寫進成果說明書（可行性）。

## 2. Demo 劇本（約 5 分鐘）

| 時間 | 場景 | 展示重點 | 觸發方式 |
|---|---|---|---|
| 0:00 | 儀表板總覽：3 段產線、機台健康度、稼動率 | 全知感知 | — |
| 0:30 | **場景 1：PPE 違規** 把組裝線攝影機切換到「人員未戴安全帽」影片 | YOLO 即時偵測 → Jev 看關鍵幀確認不是誤報 → S2 工安類 → **不叫 LLM**，直接派給班長；評審手機約 1 秒內收到通知 | 攝影機模擬器 |
| 1:30 | **場景 2：沖床卡料** | 影片出現卡料 → Jev 看關鍵幀判定卡料並**框出位置** ＋ Log 送料速率歸零 → 跨模態確認 → **Jev 回傳根因前三名和機率** → 派工通知附機率與 SOP → LLM 說明幾秒後補上 | 劇本按鈕 |
| 2:30 | **場景 2 續：現場維修** 技術員用手機和維修 Agent 對話，第一個建議無效 → Agent 給進階排查；建議中包含「伸手進模具區」→ **Jev 安全把關，標紅並要求主管確認** | 任務型 Agent＋安全把關 | 組員操作手機 |

| 4:00 | **場景 3：影像閒置但 Log 顯示運轉** | 本案代表性跨模態規則：Log 失準告警 | 劇本按鈕 |
| 4:30 | 沒人接單 → **逐級升級**：技術員 → 班長 → 組長 | 派工追蹤 | 倒數計時 |
| 4:45 | 效益頁：反應時間、MTTR、AI 成本、校準曲線 | 量化效益 | — |

**劇本按鈕**的作用：讓每個場景都能穩定重現，評審問「再一次」就能再按一次。按鈕只負責把影片片段和模擬的 Log 送進系統，**後面的判斷全部是系統即時運算**。

## 6. 可行性判斷

**整個系統做得完。** 理由：大部分元件都是成熟技術（YOLO、規則、LLM API、Discord webhook、Web 儀表板）；Jev 和 LLM 都走 API，不用自己訓練；最大的工作量在整合。

真正的風險只有三個：

| 風險 | 說明 | 對策 |
|---|---|---|
| **機台影片來源** | 沖床卡料沒有公開影片，YouTube 影片有授權問題 | 偵測問題已由 Jev 看圖解決（不用訓練）；剩下「要有影片可以播」：優先找公開工業影片資料集，找不到就自己拍替代機構。**這件事要最先處理** |
| Jev 看圖的準確度與延遲 | 官方說帶圖片的請求較慢、較不準 | 拿到 key 後第一天用 20 張圖測；不準就改成「YOLO 偵測＋Jev 只做文字判斷」 |
| 整合時間 | 模組多，串接容易出問題 | 先做最小閉環（場景 2 從頭到尾），再加其他場景 |

**兩個截止日的定位不一樣**：
- **10/30 成果說明書**：要有**最小閉環可以跑**，畫面截圖、測試數據寫進說明書。不需要所有場景都完成。
- **Demo Day（11 月）**：所有場景、攝影機模擬器、備案都到位。
